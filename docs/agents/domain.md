# Domain docs

This is a single-context repository.

Before exploring a topic, read the root `GLOSSARY.md` and any relevant ADRs in `docs/adr/`.
Use glossary terms in issue titles, specs, test names, and proposals. If an output conflicts with an ADR, surface the conflict explicitly.

The glossary and ADR directory are created or extended lazily when the domain model or a durable architectural decision requires it.
